# سامانهٔ نوبت‌دهی کلینیک — راهنمای فاز ۱ (وب + پنل مدیریت)

این پوشه شامل فاز ۱ پروژه است: هستهٔ نوبت‌دهی (که تضمین می‌کند هیچ‌وقت دو نفر
یک ساعت را همزمان نگیرند) به‌همراه یک پنل وب برای مدیریت کلینیک و ثبت دستی
نوبت. بات‌های تلگرام و بله در فازهای بعدی اضافه می‌شوند (طبق `CLAUDE.md` در
ریشهٔ مخزن).

## ۱. یک‌بار برای همیشه: نصب ابزارهای لازم روی ویندوز

۱. **Git** را نصب کنید: https://git-scm.com/download/win را باز کنید،
   فایل نصب را دانلود و اجرا کنید و همه‌جا روی «Next» بزنید.
2. **Node.js** را نصب کنید: به https://nodejs.org بروید، نسخهٔ **LTS** را
   دانلود و نصب کنید (روی «Next» بزنید، نیازی به تغییر تنظیمات نیست).
3. یک ویرایشگر کد نصب کنید (اختیاری ولی توصیه می‌شود): **VS Code** از
   https://code.visualstudio.com

بعد از نصب، یک بار کامپیوتر را ری‌استارت کنید تا مطمئن شوید همه‌چیز درست
شناسایی می‌شود.

## ۲. دریافت کد پروژه روی کامپیوتر خودتان

1. کلید ترکیبی `Win + R` را بزنید، بنویسید `cmd` و Enter بزنید تا یک پنجرهٔ
   خط فرمان (Command Prompt) باز شود.
2. این دستورها را یکی‌یکی کپی‌پیست کنید و بعد از هرکدام Enter بزنید:

```bash
cd Desktop
git clone https://github.com/omidsafarzadeh1991-rgb/omid.git
cd omid
git checkout claude/clinic-appointment-multiplatform-40h3zc
cd app
```

3. حالا وابستگی‌های پروژه را نصب کنید (این مرحله چند دقیقه طول می‌کشد):

```bash
npm install
```

4. فایل `.env` را بسازید (یک بار کافی است). این فایل تنظیمات محرمانهٔ محلی
   شماست و هرگز نباید در گیت‌هاب آپلود شود:

```bash
copy .env.example .env
```

> اگر فایل `.env.example` را ندیدید، از پشتیبانی فنی بخواهید آن را اضافه کند؛
> در حال حاضر یک نسخهٔ نمونه در همین مخزن (که کلاد ساخته) موجود است و مقدار
> `SESSION_SECRET` در آن فقط برای تست محلی است — قبل از استفادهٔ واقعی حتماً
> باید عوض شود.

5. دیتابیس محلی را بسازید:

```bash
npx prisma migrate deploy
```

## ۳. اجرای برنامه روی کامپیوتر خودتان

هر بار که خواستید برنامه را اجرا کنید:

```bash
cd Desktop\omid\app
npm run dev
```

سپس در مرورگر (Chrome/Edge) به آدرس زیر بروید:

```
http://localhost:3000
```

برای متوقف کردن برنامه، به همان پنجرهٔ خط فرمان برگردید و کلیدهای
`Ctrl + C` را بزنید.

## ۴. اجرای تست‌های خودکار (قبل از هر تغییر مهم)

```bash
npm test
```

این دستور تست‌های مربوط به هستهٔ نوبت‌دهی را اجرا می‌کند، از‌جمله تستی که
دقیقاً شبیه‌سازی می‌کند دو نفر همزمان یک ساعت را رزرو کنند و بررسی می‌کند
فقط یکی موفق شود. اگر همهٔ خط‌ها سبز (`passed`) بود، یعنی قوانین اصلی برنامه
هنوز درست کار می‌کنند.

## ۵. چک‌لیست تست دستی (با کلیک در مرورگر)

بعد از هر تغییر مهم، این مراحل را دستی هم امتحان کنید:

- [ ] ثبت‌نام یک کلینیک جدید از صفحهٔ اول (`ثبت‌نام کلینیک جدید`) با موفقیت
      انجام می‌شود و مستقیم وارد پنل می‌شوید.
- [ ] از پنل، یک پزشک جدید اضافه می‌کنید و در لیست پزشکان ظاهر می‌شود.
- [ ] روی «ثبت نوبت» کلیک می‌کنید، یک ساعت خالی انتخاب می‌کنید، نام و شمارهٔ
      بیمار را وارد و ثبت می‌کنید؛ نوبت باید در پنل زیر «نوبت‌های پیش رو»
      دیده شود.
- [ ] **تست تداخل:** همان ساعتی که الان رزرو کردید را دوباره باز کنید (رفرش
      صفحه) — آن ساعت باید به‌صورت خط‌خورده و غیرقابل‌کلیک نشان داده شود.
      اگر دو مرورگر یا دو تب همزمان باز کنید و سعی کنید هر دو دقیقاً همان
      ساعت را بزنید، فقط یکی موفق می‌شود و دیگری پیام «این ساعت همین الان
      توسط یک نفر دیگر رزرو شد» را می‌بیند.
- [ ] نوبت ثبت‌شده را از پنل لغو می‌کنید؛ آن ساعت دوباره قابل‌رزرو می‌شود.
- [ ] از پنل خارج (`خروج`) می‌شوید و دوباره با همان ایمیل/رمز وارد می‌شوید.

اگر هرکدام از این موارد کار نکرد، پیش از رفتن به فاز بعد (بات تلگرام) باید
اصلاح شود.

## ساختار فنی (برای مرجع)

- `prisma/schema.prisma` — مدل داده (کلینیک، کاربر پرسنل، پزشک، نوبت، تاریخچهٔ
  نوبت‌ها).
- `lib/booking.ts` — قلب ضدتداخل نوبت‌دهی؛ هر رزرو (از هر کانالی) باید از
  همین مسیر عبور کند.
- `lib/auth.ts`, `lib/session.ts` — ثبت‌نام کلینیک، ورود، نشست کاربر.
- `app/actions/*` — Server Actionهای فرم‌ها.
- `tests/` — تست‌های خودکار (`npm test`).
