# سامانهٔ نوبت‌دهی کلینیک — راهنمای فاز ۱ (وب + پنل مدیریت)

این پوشه شامل فاز ۱ پروژه است: هستهٔ نوبت‌دهی (که تضمین می‌کند هیچ‌وقت دو نفر
یک ساعت را همزمان نگیرند) به‌همراه یک پنل وب برای مدیریت کلینیک و ثبت دستی
نوبت. بات‌های تلگرام و بله در فازهای بعدی اضافه می‌شوند (طبق `CLAUDE.md` در
ریشهٔ مخزن).

## ۱. یک‌بار برای همیشه: نصب ابزارهای لازم روی ویندوز

۱. **Git** را نصب کنید: https://git-scm.com/download/win را باز کنید،
   فایل نصب را دانلود و اجرا کنید و همه‌جا روی «Next» بزنید.
2. **Node.js** را نصب کنید: به https://nodejs.org بروید، نسخهٔ **LTS** را
   دانلود و نصب کنید (روی «Next» بزنید، نیازی به تغییر تنظیمات نیست).
3. یک ویرایشگر کد نصب کنید (اختیاری ولی توصیه می‌شود): **VS Code** از
   https://code.visualstudio.com

بعد از نصب، یک بار کامپیوتر را ری‌استارت کنید تا مطمئن شوید همه‌چیز درست
شناسایی می‌شود.

## ۲. دریافت کد پروژه روی کامپیوتر خودتان

1. کلید ترکیبی `Win + R` را بزنید، بنویسید `cmd` و Enter بزنید تا یک پنجرهٔ
   خط فرمان (Command Prompt) باز شود.
2. این دستورها را یکی‌یکی کپی‌پیست کنید و بعد از هرکدام Enter بزنید:

```bash
cd Desktop
git clone https://github.com/omidsafarzadeh1991-rgb/omid.git
cd omid
git checkout claude/clinic-appointment-multiplatform-40h3zc
cd app
```

3. حالا وابستگی‌های پروژه را نصب کنید (این مرحله چند دقیقه طول می‌کشد):

```bash
npm install
```

4. فایل `.env` را بسازید (یک بار کافی است). این فایل تنظیمات محرمانهٔ محلی
   شماست و هرگز نباید در گیت‌هاب آپلود شود:

```bash
copy .env.example .env
```

> اگر فایل `.env.example` را ندیدید، از پشتیبانی فنی بخواهید آن را اضافه کند؛
> در حال حاضر یک نسخهٔ نمونه در همین مخزن (که کلاد ساخته) موجود است و مقدار
> `SESSION_SECRET` در آن فقط برای تست محلی است — قبل از استفادهٔ واقعی حتماً
> باید عوض شود. مقدار `SETUP_PASSWORD` هم رمزی است که فقط یک‌بار، در اولین
> اجرای برنامه روی این کامپیوتر، برای ساخت حساب کلینیک خودتان لازم دارید —
> حتماً آن را به یک رمز دلخواه خودتان تغییر دهید. `TOKEN_ENCRYPTION_KEY` هم
> برای رمزنگاری توکن‌های بات (تلگرام/بله) قبل از ذخیره در دیتابیس استفاده
> می‌شود.
>
> نکتهٔ مهم دربارهٔ معماری: این سامانه برای هر کلینیک یک نسخهٔ کاملاً جداگانه
> است — هر کلینیک برنامه را روی کامپیوتر خودش نصب می‌کند، با دیتابیس مخصوص
> به خودش، بدون هیچ سرور مشترکی با کلینیک‌های دیگر. این یعنی اطلاعات هر
> کلینیک فقط روی کامپیوتر خودشان می‌ماند.
>
> اگر از قبل یک فایل `.env` دارید و این خط‌ها را ندارد، کافی است با
> `notepad .env` بازش کنید و خط‌های جدید را از `.env.example` کپی کنید.

5. دیتابیس محلی را بسازید:

```bash
npx prisma migrate deploy
```

> **اگر هنگام اجرا خطای `Module not found: Can't resolve '@/generated/prisma/client'` دیدید:**
> این یعنی فایل‌های خودکار Prisma ساخته نشده. کافی است این دستور را بزنید و
> دوباره `npm run dev` را اجرا کنید:
>
> ```bash
> npx prisma generate
> ```

## ۳. اجرای برنامه روی کامپیوتر خودتان

⚠️ **نکتهٔ مهم دربارهٔ سرعت:** دستور `npm run dev` که تا اینجا استفاده کردیم
فقط برای توسعه و تست است و **عمداً کند** است (هر صفحه را لحظه‌ای که بازش
می‌کنید می‌سازد تا اگر کدی عوض شد سریع ببینید). برای استفادهٔ واقعی روزمره
باید از **حالت نهایی (production)** استفاده کنید که چندین برابر سریع‌تر است
(هر صفحه معمولاً کمتر از یک‌دهم ثانیه باز می‌شود، حتی روی سیستم‌های ضعیف).

برای این کار، دو فایل در پوشهٔ `app` گذاشته‌ام که کافی است رویشان **دوبار
کلیک کنید**:

- **`اجرای-برنامه.bat`** — هر روز برای روشن‌کردن برنامه همین را دوبار کلیک
  کنید. دفعهٔ اول کمی طول می‌کشد (چون باید یک‌بار برنامه را «می‌سازد»)، از
  دفعهٔ دوم به بعد در چند ثانیه بالا می‌آید.
- **`به‌روزرسانی.bat`** — فقط وقتی من تغییری در کد دادم و گفتم «به‌روزرسانی
  کنید»، این را دوبار کلیک کنید تا آخرین نسخه دانلود و آماده شود.

بعد از دوبار کلیک روی `اجرای-برنامه.bat`، یک پنجرهٔ سیاه باز می‌ماند (این را
نبندید، برنامه از همان‌جا اجرا می‌شود) و وقتی نوشت `Ready`، در مرورگر بروید به:

```
http://localhost:3000
```

برای خاموش‌کردن برنامه، همان پنجرهٔ سیاه را ببندید یا `Ctrl + C` بزنید.

> اگر می‌خواهید به‌جای دوبار کلیک از خط فرمان استفاده کنید، معادل همین دو
> فایل به‌ترتیب `npm run build && npm start` (اجرا) و
> `git pull && npm install && npm run build` (به‌روزرسانی) است.

## ۴. اجرای تست‌های خودکار (قبل از هر تغییر مهم)

```bash
npm test
```

این دستور تست‌های مربوط به هستهٔ نوبت‌دهی را اجرا می‌کند، از‌جمله تستی که
دقیقاً شبیه‌سازی می‌کند دو نفر همزمان یک ساعت را رزرو کنند و بررسی می‌کند
فقط یکی موفق شود. اگر همهٔ خط‌ها سبز (`passed`) بود، یعنی قوانین اصلی برنامه
هنوز درست کار می‌کنند.

## ۵. چک‌لیست تست دستی (با کلیک در مرورگر)

بعد از هر تغییر مهم، این مراحل را دستی هم امتحان کنید:

- [ ] از صفحهٔ اول روی «راه‌اندازی اولیهٔ سامانه» بزنید (این دکمه فقط تا وقتی
      هیچ کلینیکی ساخته نشده دیده می‌شود)، رمز `SETUP_PASSWORD` و اطلاعات
      کلینیک/مدیر را وارد کنید — باید مستقیم و بدون مرحلهٔ اضافه وارد داشبورد
      شوید. حسابی که همین‌جا می‌سازید **مالک سامانه (OWNER)** است — تنها حساب
      این نصب که به توکن‌ها، لاگ امنیتی و بک‌آپ دسترسی دارد (بخش ۸).
- [ ] از پنل خارج شوید؛ حالا صفحهٔ اول باید فقط «ورود به پنل» را نشان بدهد
      (نه دکمهٔ راه‌اندازی) و اگر مستقیم آدرس `/setup` را باز کنید، باید به
      صفحهٔ ورود هدایت شوید — چون راه‌اندازی قبلاً یک‌بار انجام شده.
- [ ] با همان ایمیل/رمزی که برای مدیر کلینیک ساختید از صفحهٔ ورود وارد شوید.
- [ ] در داشبورد، کارت‌های آمار (پزشکان، نوبت‌های امروز، …) را می‌بینید و
      همه صفر هستند چون هنوز پزشکی اضافه نشده.
- [ ] در «مدیریت پزشکان»، اول یکی‌دو تخصص (مثل «ارتودنسی») و یکی‌دو خدمت با
      قیمت (مثل «ویزیت عمومی» با قیمت ۲۰۰۰۰۰) را در دو فهرست بالای صفحه اضافه
      کنید — این‌ها یک‌بار برای کل کلینیک تعریف می‌شوند.
- [ ] یک پزشک جدید اضافه می‌کنید — برای هر روز کاری می‌توانید ساعت متفاوت
      بگذارید (مثلاً شنبه از ۱۰ تا ۱۸، اما چهارشنبه از ۱۲ تا ۱۵) و از فهرست
      تخصص‌ها/خدماتی که ساختید با تیک‌زدن چندتا انتخاب کنید؛ در لیست پزشکان
      با ساعت‌های هر روز، تخصص‌ها و خدماتش ظاهر می‌شود و کارت «پزشکان» به ۱
      تغییر می‌کند.
- [ ] روی «ویرایش تخصص‌ها و خدمات» زیر همان پزشک کلیک کنید — باید بتوانید
      تیک‌ها را عوض و «ذخیره» کنید؛ تغییر باید فوراً در همان لیست دیده شود.
- [ ] در داشبورد، روی «نوبت برای دکتر …» (داخل بنر «ثبت نوبت جدید») کلیک
      کنید — باید یک **پاپ‌آپ** همان‌جا باز شود (نه صفحهٔ جدید)، با تقویم ماه
      و ساعت‌های خالی همان پزشک. یک روز و ساعت انتخاب، نام/شماره را وارد و
      «ثبت نوبت» را بزنید — پاپ‌آپ باید خودش بسته شود و نوبت فوراً زیر
      «نوبت‌های پیش رو» (گروه‌بندی‌شده بر اساس «امروز»/«فردا»/تاریخ) و در
      کارت‌های آمار دیده شود، بدون رفرش دستی صفحه.
- [ ] روی «ثبت نوبت» کلیک می‌کنید — یک تقویم ماهانه بزرگ می‌بینید. روزهایی که
      پزشک کار **نمی‌کند** (مثلاً جمعه) خاکستری و غیرقابل‌کلیک هستند؛ روزهای
      کاری تعداد ساعت خالی («۱۶ خالی») را نشان می‌دهند.
- [ ] یک روز کاری را کلیک می‌کنید — پایین تقویم، ساعت‌های آن روز باز می‌شود.
      یک ساعت خالی انتخاب می‌کنید، نوع خدمت را از لیست انتخاب می‌کنید، نام و
      شمارهٔ بیمار را وارد و ثبت می‌کنید؛ نوبت باید در پنل زیر «نوبت‌های پیش
      رو» با یک نشان رنگی («ثبت دستی» با آیکون مداد) و نام خدمت دیده شود،
      کارت‌های آمار به‌روز شوند، و همان روز در تقویم یک عدد کمتر («۱۵ خالی»)
      نشان بدهد.
- [ ] در داشبورد، بخش «نوبت‌ها از کدام کانال بیشتر ثبت می‌شود» را ببینید —
      فعلاً باید فقط «ثبت دستی» را نشان دهد (چون هنوز بات‌ها فعال نیستند).
- [ ] از منوی کناری وارد «تنظیمات بات‌ها» شوید، یک متن آزمایشی در قسمت
      «تلگرام» بچسبانید و «ذخیرهٔ توکن» را بزنید — باید پیام تأیید با چند
      حرف آخر توکن (نه کل آن) ببینید و وضعیت به «فعال» تغییر کند. روی
      «غیرفعال کردن» بزنید و مطمئن شوید وضعیت عوض می‌شود.
- [ ] **تست تداخل:** همان ساعتی که الان رزرو کردید را دوباره باز کنید (رفرش
      صفحه) — آن ساعت باید به‌صورت خط‌خورده و غیرقابل‌کلیک نشان داده شود.
      اگر دو مرورگر یا دو تب همزمان باز کنید و سعی کنید هر دو دقیقاً همان
      ساعت را بزنید، فقط یکی موفق می‌شود و دیگری پیام «این ساعت همین الان
      توسط یک نفر دیگر رزرو شد» را می‌بیند.
- [ ] نوبت ثبت‌شده را از پنل لغو می‌کنید؛ آن ساعت دوباره قابل‌رزرو می‌شود.
- [ ] از پنل خارج (`خروج`) می‌شوید و دوباره با همان ایمیل/رمز وارد می‌شوید.
- [ ] **تست دسترسی‌ها:** از منوی کناری وارد «کارمندان» شوید و یک کاربر جدید
      با نقش «منشی» بسازید. خارج شوید و با ایمیل/رمز همان منشی وارد شوید —
      باید فقط «داشبورد» را در منو ببیند (نه «پزشکان» و نه «کارمندان»)، کارت‌های
      آمار را نبیند، ولی بتواند نوبت جدید ثبت کند و نوبت‌های پیش رو را ببیند.
      اگر مستقیم آدرس `/dashboard/doctors` یا `/dashboard/staff` را در مرورگر
      تایپ کند، باید خودکار به داشبورد برگردد.

اگر هرکدام از این موارد کار نکرد، پیش از رفتن به فاز بعد (بات تلگرام) باید
اصلاح شود.

## ۶. بات تلگرام با هوش مصنوعی (فاز ۲)

از این مرحله به بعد، بیماران می‌توانند مستقیم در تلگرام با یک هوش مصنوعی که
مثل منشی مطب رفتار می‌کند چت کنند و نوبت بگیرند. توجه: **برخلاف بقیهٔ پنل، این
بخش ذاتاً به اینترنت نیاز دارد** (تلگرام باید بتواند پیام‌ها را به کامپیوتر شما
برساند) — این یک قدم به عقب در مورد «بدون نیاز به اینترنت» نیست، بلکه یک
ویژگی از جنس دیگر است که فقط با اتصال به تلگرام معنا دارد.

هر پیامی که هوش مصنوعی رد و بدل می‌کند هزینهٔ کمی از حساب سرویس هوش مصنوعی
که انتخاب می‌کنید کم می‌کند. بات به یک شرکت خاص وابسته نیست — از طریق یک
آدرس API قابل‌تنظیم (`AI_BASE_URL`) با هر سرویسی که با فرمت OpenAI سازگار
باشد کار می‌کند؛ پیش‌فرض [OpenRouter](https://openrouter.ai) است چون با یک
کلید به مدل‌های زیادی (از جمله گزینه‌های رایگان/ارزان) دسترسی می‌دهد.

### ۶.۱. ساخت بات در تلگرام

1. در تلگرام دنبال حساب `@BotFather` بگردید و چت را باز کنید.
2. دستور `/newbot` را بفرستید و نام و یک نام‌کاربری (باید به `bot` ختم شود،
   مثلاً `ClinicXBot`) برای بات انتخاب کنید.
3. BotFather یک توکن می‌فرستد شبیه `123456789:AAF...` — این را جایی امن کپی
   کنید (فقط همین یک‌بار نمایش داده می‌شود؛ اگر گم شد از `/token` در همان چت
   دوباره بگیرید).

### ۶.۲. گرفتن کلید هوش مصنوعی و وارد کردنش

1. به https://openrouter.ai بروید، حساب بسازید و یک API Key بسازید (یا اگر
   ترجیح می‌دهید مستقیم از OpenAI یا سرویس دیگری کلید بگیرید — کافی است
   `AI_BASE_URL` را هم متناسب با آن عوض کنید).
2. فایل `.env` پروژه (داخل پوشهٔ `app`) را با Notepad باز کنید:

```bash
notepad .env
```

3. مقدار `AI_API_KEY` را با کلید واقعی خودتان جایگزین کنید؛ اگر لازم بود
   `AI_MODEL` را هم به مدل دلخواهتان تغییر بدهید (فهرست مدل‌ها و قیمتشان در
   https://openrouter.ai/models است). فایل را ذخیره کنید. **این کلید را
   هرگز در چت یا جای دیگری با من (کلود) به اشتراک نگذارید** — فقط داخل همین
   فایل محلی روی کامپیوتر خودتان.
4. اگر برنامه در حال اجراست، پنجرهٔ سیاه را ببندید و دوباره
   `اجرای-برنامه.bat` را اجرا کنید تا مقدار جدید خوانده شود.

### ۶.۳. نصب و اجرای ngrok (برای رساندن پیام‌های تلگرام به کامپیوتر شما)

1. از https://ngrok.com/download نسخهٔ ویندوز را دانلود و از حالت فشرده خارج
   کنید.
2. یک حساب رایگان در ngrok بسازید و از صفحهٔ داشبورد آن‌ها، دستور
   `ngrok config add-authtoken <توکن-شما>` را کپی و در همان پوشه‌ای که
   `ngrok.exe` را باز کرده‌اید اجرا کنید.
3. مطمئن شوید برنامهٔ کلینیک با `اجرای-برنامه.bat` در حال اجراست (پورت
   ۳۰۰۰)، سپس در یک پنجرهٔ Command Prompt جدید این را اجرا کنید:

```bash
ngrok http 3000
```

4. ngrok یک آدرس می‌دهد شبیه `https://abcd-1-2-3-4.ngrok-free.app` — این
   پنجره را باز نگه دارید (تا وقتی بات باید کار کند)، چون با بستنش آدرس عوض
   می‌شود.

### ۶.۴. وصل‌کردن توکن تلگرام و ثبت webhook

1. از داشبورد وارد «تنظیمات بات‌ها» شوید، توکن تلگرامی که از BotFather
   گرفتید را در قسمت «تلگرام» بچسبانید و «ذخیرهٔ توکن» را بزنید.
2. زیر همان بخش، یک دستور curl آماده می‌بینید. آن را کپی کنید و در آن:
   - به‌جای `<آدرس-ngrok-شما>` آدرس واقعی مرحلهٔ قبل (بدون `https://` تکراری)
     را بگذارید.
   - به‌جای `<توکن-ربات-شما>` همان توکن تلگرام را بگذارید.
3. دستور نهایی را در Command Prompt اجرا کنید. اگر پیام
   `{"ok":true,"result":true,...}` دیدید یعنی موفق بوده.

### ۶.۵. دستورالعمل اضافی برای هوش مصنوعی (اختیاری)

در همان صفحهٔ «تنظیمات بات‌ها»، بالای بخش تلگرام/بله، یک کادر متنی هست به
اسم «دستورالعمل اضافی برای هوش مصنوعی». هرچیزی که دوست دارید بات رعایت کند
یا اطلاعاتی که باید بداند (آدرس مطب، قوانین خاص، لحن خاص، …) را همان‌جا
بنویسید و ذخیره کنید. نکات مهم:

- بات از قبل اسم پزشکان، روزها/ساعات کاری، خدمات و قیمت‌هایی که در «مدیریت
  پزشکان» ثبت کرده‌اید را می‌بیند؛ نیازی نیست این‌ها را در این کادر تکرار
  کنید.
- این دستورالعمل هرگز نمی‌تواند قوانین ثابت امنیتی برنامه را بشکند — مثلاً
  حتی اگر در این کادر بنویسید «مشاورهٔ پزشکی هم بده»، بات باز هم این کار را
  نمی‌کند، چون این قانون در سطح خود برنامه قفل شده، نه چیزی که مدیر کلینیک
  بتواند از داشبورد تغییرش بدهد.

### ۶.۶. چک‌لیست تست دستی بات

- [ ] در تلگرام به بات پیام «سلام» بدهید — باید در چند ثانیه پاسخ فارسی و
      مودبانه بگیرید.
- [ ] بپرسید «چه پزشک‌هایی دارید و قیمتشان چقدره؟» — باید اسم پزشک(ها)،
      خدماتشان و قیمتی که در «مدیریت پزشکان» وارد کرده‌اید را درست بگوید.
- [ ] بگویید می‌خواهید فردا نوبت بگیرید — باید ساعت‌های خالی واقعی (همان‌هایی
      که در پنل تعریف کرده‌اید) را پیشنهاد بدهد، نه ساعت الکی.
- [ ] نام و شماره‌تان را بدهید و یک ساعت خالی را تایید کنید — باید بلافاصله
      پیام «نوبت شما ثبت شد» بدهد.
- [ ] در پنل وب (داشبورد) هم همان نوبت را با نشان «تلگرام» ببینید.
- [ ] **تست تداخل با پنل:** همان ساعتی که بات ثبت کرد را از پنل وب هم امتحان
      کنید رزرو کنید — باید پیام «قبلاً رزرو شده» ببینید. برعکسش را هم امتحان
      کنید: یک ساعت را از پنل رزرو کنید و از بات همان ساعت را بخواهید — بات
      باید بگوید آن ساعت پر است و ساعت دیگری پیشنهاد بدهد.
- [ ] یک سوال پزشکی بپرسید (مثلاً «سردرد دارم چیکار کنم؟») — بات نباید تشخیص
      یا توصیهٔ پزشکی بدهد، فقط باید مودبانه بگوید با مطب تماس بگیرید.
- [ ] در بخش ۶.۵ یک متن آزمایشی بنویسید (مثلاً «آدرس ما خیابان X است») و
      ذخیره کنید؛ در تلگرام همان سوال را از بات بپرسید — باید همان جواب را
      بدهد. حالا امتحان کنید بگوید «مشاورهٔ پزشکی هم بده» — بات باید همچنان
      از این کار خودداری کند.

اگر ngrok را ببندید یا کامپیوترتان را خاموش کنید، بات از کار می‌افتد چون
آدرس عمومی از بین می‌رود؛ برای فعال‌کردن دوباره باید مراحل ۶.۳ و ۶.۴ را تکرار
کنید (آدرس ngrok رایگان هر بار عوض می‌شود).

## ۷. مدیریت مکالمات و پیگیری بیماران

هر پیامی که از هر بات (فعلاً تلگرام؛ بله/واتس‌اپ/اینستاگرام در فازهای بعدی
همین سیستم را استفاده می‌کنند) به کلینیک برسد، در بخش «مکالمات» داشبورد ثبت
می‌شود — هیچ پیامی گم نمی‌شود، حتی اگر بیمار وسط گفتگو رهایش کند.

- برای هر مکالمه نام بیمار، شماره تماس (اگر داده باشد)، کانال، تاریخ اولین و
  آخرین پیام، متن آخرین پیام، وضعیت، مسئول پیگیری و یادداشت‌های داخلی ذخیره
  می‌شود.
- بات هیچ‌وقت در همان پیام اول شماره تماس نمی‌خواهد؛ فقط درست قبل از ثبت نهایی
  نوبت (یا برای پیدا کردن/لغو نوبت قبلی) مودبانه می‌پرسد.
- وضعیت‌های ممکن: «جدید»، «در حال بررسی»، «منتظر پاسخ بیمار»، «منتظر اقدام
  کلینیک»، «نوبت ثبت شد»، «ناتمام»، «بسته شده».
- اگر بیمار وسط گفتگو دیگر جواب ندهد، مکالمه حذف نمی‌شود؛ بعد از ۲ ساعت
  خودکار به وضعیت «ناتمام» می‌رود تا بعداً بتوانید پیگیری کنید.
- اگر مکالمه‌ای بیش از ۳۰ دقیقه بدون پاسخ کلینیک بماند، در فهرست با نشان
  «نیاز به پیگیری» علامت می‌خورد و تعدادش هم کنار «مکالمات» در منوی کناری و
  هم در کارت‌های بالای همان صفحه نشان داده می‌شود.
- دکمه‌های «تماس با بیمار»، «ثبت نتیجهٔ تماس»، «ثبت یادداشت» و «تغییر وضعیت»
  روی صفحهٔ هر مکالمه در دسترس‌اند؛ همهٔ یادداشت‌ها و تغییرات وضعیت با تاریخ و
  نام کارمند ثبت‌کننده نگه داشته می‌شوند و هرگز پاک نمی‌شوند.
- جست‌وجوی سریع بر اساس نام، شماره موبایل، شناسهٔ پیام‌رسان، پزشک و وضعیت در
  همان صفحه وجود دارد.

### ۷.۱. چک‌لیست تست دستی مکالمات

- [ ] در تلگرام به بات فقط بگویید «سلام» — در پنل، صفحهٔ «مکالمات» یک ردیف
      جدید با وضعیت «جدید» ببینید، بدون این‌که نام یا شماره‌ای خواسته شده باشد.
- [ ] بگویید «قیمت خدماتتون چقدره؟» — بات باید مستقیم جواب بدهد، نه این‌که اول
      نام و شماره بخواهد.
- [ ] یک نوبت را کامل رزرو کنید — درست همین‌جا (و نه زودتر) بات باید بپرسد
      «برای اینکه در صورت نیاز بتونیم تماس بگیریم، لطفاً شماره‌تون رو وارد
      کنید.»؛ بعد از ثبت، وضعیت مکالمه باید «نوبت ثبت شد» شود.
- [ ] بگویید «نوبتم چه ساعتیه؟» یا «نوبتمو لغو کن» — بات باید اول شماره تماس
      را بپرسد (اگر ندارد) و فقط از روی نوبت‌های واقعی همان شماره جواب بدهد.
- [ ] در پنل، روی یک مکالمه «تغییر وضعیت»، «ثبت یادداشت» و «ثبت نتیجهٔ تماس»
      را امتحان کنید — همه باید فوراً در «تاریخچهٔ پیگیری» همان مکالمه ظاهر
      شوند.
- [ ] جست‌وجو را با بخشی از شماره تماس یا نام امتحان کنید — فقط مکالمهٔ درست
      باید نشان داده شود.

## ۸. مالک سامانه، امنیت، بک‌آپ و پیامک یادآوری

### ۸.۱. نقش «مالک سامانه» (OWNER)

هر نصب دقیقاً یک حساب «مالک سامانه» دارد — همان حسابی که با `/setup` ساخته
می‌شود. این حساب یک لایهٔ بالاتر از «مدیر کلینیک» است:

| کار | مالک سامانه (OWNER) | مدیر کلینیک (ADMIN) | منشی (RECEPTIONIST) |
|---|---|---|---|
| دیدن/تغییر توکن بات‌ها و کلید سرویس پیامک | ✅ | ❌ (فقط پیام «از مالک سامانه بخواهید») | ❌ |
| فعال/غیرفعال‌کردن بات و پیامک، ویرایش متن‌ها | ✅ | ✅ | ❌ |
| لاگ امنیتی و بک‌آپ دستی | ✅ (صفحهٔ «امنیت و بک‌آپ») | ❌ | ❌ |
| پزشکان، کارمندان، کاتالوگ، نوبت‌ها | ✅ | ✅ | فقط ثبت/دیدن نوبت |

فقط یک OWNER در هر نصب می‌تواند وجود داشته باشد — این هم در دیتابیس (قید
یکتا) و هم در فرم «افزودن کارمند» (که اصلاً گزینهٔ OWNER را نشان نمی‌دهد)
تضمین شده.

### ۸.۲. صفحهٔ «امنیت و بک‌آپ» (فقط مالک سامانه)

از منوی کناری در دسترس است و شامل: سلامت سیستم (حجم دیتابیس، تعداد نوبت‌ها)،
دکمهٔ «ساخت بک‌آپ دستی الان» (یک کپی کامل و سالم از دیتابیس در پوشهٔ
`backups` می‌سازد و فقط ۷ نسخهٔ آخر را نگه می‌دارد)، و لاگ امنیتی (ورود
موفق/ناموفق، تغییر توکن، تغییر تنظیمات پیامک، ساخت بک‌آپ).

> بک‌آپ خودکار روزانه (بدون نیاز به کلیک دستی) هنوز طراحی/پیاده‌سازی نشده؛
> فعلاً فقط بک‌آپ دستی آماده است.

### ۸.۳. پیامک یادآوری نوبت

از صفحهٔ «تنظیمات بات‌ها و پیامک» قابل تنظیم است. سه نوع پیامک پشتیبانی
می‌شود، هرکدام جدا فعال/غیرفعال و متنش قابل‌ویرایش:

- تایید فوری بعد از ثبت نوبت (هر کانالی که باشد).
- یادآوری ۲۴ ساعت قبل از نوبت.
- یادآوری ۲ تا ۴ ساعت قبل از نوبت.

پیامک واقعاً هزینه دارد و از حساب پیامکی خودتان کسر می‌شود؛ **تا وقتی مالک
سامانه کلید سرویس پیامک را وارد نکند، هیچ پیامکی ارسال نمی‌شود** — دقیقاً
مثل توکن بات‌ها و کلید هوش مصنوعی.

سرویس پیش‌فرض پیاده‌سازی‌شده کاوه‌نگار است، اما لایهٔ ارسال پیامک (مثل
لایهٔ پیام‌رسان‌ها) پشت یک adapter مشترک است؛ افزودن ملی‌پیامک یا فراپیامک
در آینده فقط به یک فایل جدید مثل `lib/sms/kavenegar.ts` نیاز دارد.

چون یادآوری‌های ۲۴ ساعته و ۲ تا ۴ ساعته به زمان وابسته‌اند (نه به باز بودن
پنل)، یک بررسی‌کنندهٔ پس‌زمینه هر ۱۵ دقیقه اجرا می‌شود (فایل
`instrumentation.ts`) — تا وقتی برنامه روشن است (`npm start` در حال اجراست)،
این یادآوری‌ها به‌موقع ارسال می‌شوند.

### ۸.۴. چک‌لیست تست دستی

- [ ] با حساب مالک سامانه وارد شوید — در منوی کناری «امنیت و بک‌آپ» را
      می‌بینید؛ یک کارمند جدید با نقش «مدیر کلینیک» بسازید.
- [ ] خارج شوید و با همان کارمند مدیر کلینیک وارد شوید — در «تنظیمات بات‌ها
      و پیامک» باید فرم واردکردن توکن/کلید پیامک را **نبینید**، فقط بتوانید
      فعال/غیرفعال کنید و متن پیامک‌ها را ویرایش کنید. اگر مستقیم آدرس
      `/dashboard/owner` را باز کنید، باید به داشبورد برگردید.
- [ ] با حساب مالک سامانه، در «تنظیمات بات‌ها و پیامک» کلید یک سرویس پیامک
      (حتی یک کلید آزمایشی) را ذخیره کنید — در «امنیت و بک‌آپ» باید یک ردیف
      جدید «تغییر تنظیمات پیامک» در لاگ امنیتی ببینید.
- [ ] در «امنیت و بک‌آپ» روی «ساخت بک‌آپ دستی الان» بزنید — پیام موفقیت و
      یک فایل جدید در فهرست بک‌آپ‌ها ببینید.

## ساختار فنی (برای مرجع)

- `prisma/schema.prisma` — مدل داده (کلینیک، کاربر پرسنل، پزشک، نوبت، تاریخچهٔ
  نوبت‌ها).
- `lib/booking.ts` — قلب ضدتداخل نوبت‌دهی؛ هر رزرو (از هر کانالی) باید از
  همین مسیر عبور کند. `buildMonthGrid` هم اینجاست: منطق ساخت شبکهٔ ماهانه
  (روز کاری/پر/خالی) که هم صفحهٔ کامل `/book/[doctorId]` و هم پاپ‌آپ ثبت
  سریع نوبت در داشبورد از همان یک تابع استفاده می‌کنند تا هیچ‌وقت از هم
  عقب نیفتند.
- `app/dashboard/NewAppointmentCard.tsx`, `app/dashboard/QuickBookModal.tsx` —
  بنر «ثبت نوبت جدید» و پاپ‌آپ ثبت نوبت در همان صفحهٔ داشبورد (تقویم ماهانه +
  انتخاب ساعت + فرم)؛ ثبت نهایی از همان Server Action صفحهٔ نوبت‌دهی
  (`createManualAppointmentAction`) استفاده می‌کند، نه یک مسیر جدا.
- `app/dashboard/UpcomingList.tsx` — نمایش «نوبت‌های پیش رو» گروه‌بندی‌شده بر
  اساس روز (امروز/فردا/تاریخ).
- `lib/auth.ts`, `lib/session.ts` — ثبت‌نام کلینیک، ورود، نشست کاربر.
- `lib/setup.ts` — بررسی رمز راه‌اندازی و این‌که آیا کلینیک قبلاً ساخته شده؛
  صفحهٔ `/setup` فقط تا وقتی هیچ کلینیکی وجود ندارد قابل‌دسترس است (هر نصب
  همیشه فقط یک کلینیک دارد، هیچ سرور مشترکی بین کلینیک‌ها نیست).
- `lib/settings.ts` — ذخیرهٔ رمزنگاری‌شدهٔ توکن بات‌ها و رمز webhook هر کلینیک.
- `lib/telegram.ts` — ارسال پیام به تلگرام از طریق Bot API.
- `lib/assistant.ts` — موتور گفتگوی هوش مصنوعی (از طریق هر سرویس سازگار با
  فرمت OpenAI، پیش‌فرض OpenRouter)؛ فقط از طریق ابزارهای مشخص (`list_doctors`,
  `check_availability`, `book_appointment`, `find_my_appointments`,
  `cancel_appointment`, `escalate_to_staff`) به `lib/booking.ts` وصل می‌شود و
  هرگز خودش دربارهٔ خالی‌بودن یک ساعت تصمیم نمی‌گیرد؛ بعد از هر پیام، رکورد
  مکالمه (`BotConversation`) را هم به‌روز می‌کند.
- `app/api/telegram/webhook/[clinicId]/route.ts` — نقطهٔ ورودی وبهوک تلگرام؛
  امضای هر درخواست را قبل از پردازش تایید می‌کند.
- `lib/conversations.ts` — منطق پیگیری مکالمات: تشخیص «نیاز به پیگیری»،
  تشخیص خودکار مکالمات «ناتمام» (بدون نیاز به سرویس پس‌زمینه)، تغییر وضعیت،
  ثبت یادداشت/نتیجهٔ تماس، و آمار داشبورد مکالمات.
- `app/dashboard/conversations` — فهرست و صفحهٔ جزئیات هر مکالمه.
- `app/dashboard/doctors`, `app/dashboard/staff` — صفحات مخصوص «مدیر کلینیک»
  (نقش ADMIN و OWNER؛ تابع مشترک `canManageClinic` در `lib/roles.ts`)؛ نقش
  «منشی» (RECEPTIONIST) به این صفحات دسترسی ندارد و در صورت تلاش، به داشبورد
  برمی‌گردد. این بررسی هم در صفحه و هم داخل Server Actionهای مربوطه انجام
  می‌شود.
- `lib/roles.ts` — تابع مشترک `canManageClinic(role)` (OWNER یا ADMIN)؛
  `lib/dal.ts` هم `requireOwner()` را دارد، برای صفحات/اکشن‌های مخصوص مالک
  سامانه.
- `lib/security-log.ts` — لاگ append-only رویدادهای امنیتی (ورود، تغییر
  توکن/پیامک، ساخت بک‌آپ)؛ فقط برای OWNER قابل مشاهده.
- `lib/backup.ts` — بک‌آپ دستی با `VACUUM INTO` (کپی کامل و سالم حتی حین
  کارکردن برنامه) و نگه‌داری فقط ۷ نسخهٔ آخر؛ `app/dashboard/owner` صفحهٔ
  نمایش/تریگر آن است.
- `lib/sms/` — لایهٔ adapter پیامک (`types.ts` اینترفیس مشترک،
  `kavenegar.ts` پیاده‌سازی اول، `index.ts` انتخاب provider بر اساس تنظیمات
  هر کلینیک و رمزگشایی کلید). `lib/reminders.ts` منطق زمان‌بندی (تایید فوری
  از داخل `bookAppointment`، یادآوری ۲۴ و ۲-۴ ساعته از طریق `sweepDueReminders`
  که هر ۱۵ دقیقه در `instrumentation.ts` اجرا می‌شود)؛ جدول `AppointmentReminder`
  با قید یکتا روی (appointmentId, type) تضمین می‌کند هیچ پیامکی دوبار ارسال
