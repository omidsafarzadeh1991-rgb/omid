# سامانهٔ نوبت‌دهی کلینیک — راهنمای فاز ۱ (وب + پنل مدیریت)

این پوشه شامل فاز ۱ پروژه است: هستهٔ نوبت‌دهی (که تضمین می‌کند هیچ‌وقت دو نفر
یک ساعت را همزمان نگیرند) به‌همراه یک پنل وب برای مدیریت کلینیک و ثبت دستی
نوبت. بات‌های تلگرام و بله در فازهای بعدی اضافه می‌شوند (طبق `CLAUDE.md` در
ریشهٔ مخزن).

## ۱. یک‌بار برای همیشه: نصب ابزارهای لازم روی ویندوز

۱. **Git** را نصب کنید: https://git-scm.com/download/win را باز کنید،
   فایل نصب را دانلود و اجرا کنید و همه‌جا روی «Next» بزنید.
2. **Node.js** را نصب کنید: به https://nodejs.org بروید، نسخهٔ **LTS** را
   دانلود و نصب کنید (روی «Next» بزنید، نیازی به تغییر تنظیمات نیست).
3. یک ویرایشگر کد نصب کنید (اختیاری ولی توصیه می‌شود): **VS Code** از
   https://code.visualstudio.com

بعد از نصب، یک بار کامپیوتر را ری‌استارت کنید تا مطمئن شوید همه‌چیز درست
شناسایی می‌شود.

## ۲. دریافت کد پروژه روی کامپیوتر خودتان

1. کلید ترکیبی `Win + R` را بزنید، بنویسید `cmd` و Enter بزنید تا یک پنجرهٔ
   خط فرمان (Command Prompt) باز شود.
2. این دستورها را یکی‌یکی کپی‌پیست کنید و بعد از هرکدام Enter بزنید:

```bash
cd Desktop
git clone https://github.com/omidsafarzadeh1991-rgb/omid.git
cd omid
git checkout claude/clinic-appointment-multiplatform-40h3zc
cd app
```

3. حالا وابستگی‌های پروژه را نصب کنید (این مرحله چند دقیقه طول می‌کشد):

```bash
npm install
```

4. فایل `.env` را بسازید (یک بار کافی است). این فایل تنظیمات محرمانهٔ محلی
   شماست و هرگز نباید در گیت‌هاب آپلود شود:

```bash
copy .env.example .env
```

> اگر فایل `.env.example` را ندیدید، از پشتیبانی فنی بخواهید آن را اضافه کند؛
> در حال حاضر یک نسخهٔ نمونه در همین مخزن (که کلاد ساخته) موجود است و مقدار
> `SESSION_SECRET` در آن فقط برای تست محلی است — قبل از استفادهٔ واقعی حتماً
> باید عوض شود. مقدار `SUPERADMIN_PASSWORD` هم رمز ورود شما (مدیر کل سامانه)
> برای ساخت کلینیک جدید است — حتماً آن را به یک رمز دلخواه خودتان تغییر دهید.

5. دیتابیس محلی را بسازید:

```bash
npx prisma migrate deploy
```

> **اگر هنگام اجرا خطای `Module not found: Can't resolve '@/generated/prisma/client'` دیدید:**
> این یعنی فایل‌های خودکار Prisma ساخته نشده. کافی است این دستور را بزنید و
> دوباره `npm run dev` را اجرا کنید:
>
> ```bash
> npx prisma generate
> ```

## ۳. اجرای برنامه روی کامپیوتر خودتان

⚠️ **نکتهٔ مهم دربارهٔ سرعت:** دستور `npm run dev` که تا اینجا استفاده کردیم
فقط برای توسعه و تست است و **عمداً کند** است (هر صفحه را لحظه‌ای که بازش
می‌کنید می‌سازد تا اگر کدی عوض شد سریع ببینید). برای استفادهٔ واقعی روزمره
باید از **حالت نهایی (production)** استفاده کنید که چندین برابر سریع‌تر است
(هر صفحه معمولاً کمتر از یک‌دهم ثانیه باز می‌شود، حتی روی سیستم‌های ضعیف).

برای این کار، دو فایل در پوشهٔ `app` گذاشته‌ام که کافی است رویشان **دوبار
کلیک کنید**:

- **`اجرای-برنامه.bat`** — هر روز برای روشن‌کردن برنامه همین را دوبار کلیک
  کنید. دفعهٔ اول کمی طول می‌کشد (چون باید یک‌بار برنامه را «می‌سازد»)، از
  دفعهٔ دوم به بعد در چند ثانیه بالا می‌آید.
- **`به‌روزرسانی.bat`** — فقط وقتی من تغییری در کد دادم و گفتم «به‌روزرسانی
  کنید»، این را دوبار کلیک کنید تا آخرین نسخه دانلود و آماده شود.

بعد از دوبار کلیک روی `اجرای-برنامه.bat`، یک پنجرهٔ سیاه باز می‌ماند (این را
نبندید، برنامه از همان‌جا اجرا می‌شود) و وقتی نوشت `Ready`، در مرورگر بروید به:

```
http://localhost:3000
```

برای خاموش‌کردن برنامه، همان پنجرهٔ سیاه را ببندید یا `Ctrl + C` بزنید.

> اگر می‌خواهید به‌جای دوبار کلیک از خط فرمان استفاده کنید، معادل همین دو
> فایل به‌ترتیب `npm run build && npm start` (اجرا) و
> `git pull && npm install && npm run build` (به‌روزرسانی) است.

## ۴. اجرای تست‌های خودکار (قبل از هر تغییر مهم)

```bash
npm test
```

این دستور تست‌های مربوط به هستهٔ نوبت‌دهی را اجرا می‌کند، از‌جمله تستی که
دقیقاً شبیه‌سازی می‌کند دو نفر همزمان یک ساعت را رزرو کنند و بررسی می‌کند
فقط یکی موفق شود. اگر همهٔ خط‌ها سبز (`passed`) بود، یعنی قوانین اصلی برنامه
هنوز درست کار می‌کنند.

## ۵. چک‌لیست تست دستی (با کلیک در مرورگر)

بعد از هر تغییر مهم، این مراحل را دستی هم امتحان کنید:

- [ ] از صفحهٔ اول روی «ورود مدیر کل سامانه» بزنید، با رمز `SUPERADMIN_PASSWORD`
      وارد شوید و از `/superadmin` یک کلینیک جدید بسازید (نام کلینیک، نام و
      ایمیل و رمز مدیر کلینیک را وارد کنید).
- [ ] خارج شوید و این‌بار از صفحهٔ اول روی «ورود به پنل کلینیک» بزنید و با
      همان ایمیل/رمزی که برای مدیر کلینیک ساختید وارد شوید.
- [ ] در داشبورد، کارت‌های آمار (پزشکان، نوبت‌های امروز، …) را می‌بینید و
      همه صفر هستند چون هنوز پزشکی اضافه نشده.
- [ ] یک پزشک جدید اضافه می‌کنید؛ در بخش «ثبت نوبت جدید» بالای داشبورد و در
      لیست پزشکان ظاهر می‌شود و کارت «پزشکان» به ۱ تغییر می‌کند.
- [ ] روی «ثبت نوبت» کلیک می‌کنید، یک ساعت خالی انتخاب می‌کنید، نام و شمارهٔ
      بیمار را وارد و ثبت می‌کنید؛ نوبت باید در پنل زیر «نوبت‌های پیش رو»
      دیده شود و کارت‌های آمار به‌روز شوند.
- [ ] **تست تداخل:** همان ساعتی که الان رزرو کردید را دوباره باز کنید (رفرش
      صفحه) — آن ساعت باید به‌صورت خط‌خورده و غیرقابل‌کلیک نشان داده شود.
      اگر دو مرورگر یا دو تب همزمان باز کنید و سعی کنید هر دو دقیقاً همان
      ساعت را بزنید، فقط یکی موفق می‌شود و دیگری پیام «این ساعت همین الان
      توسط یک نفر دیگر رزرو شد» را می‌بیند.
- [ ] نوبت ثبت‌شده را از پنل لغو می‌کنید؛ آن ساعت دوباره قابل‌رزرو می‌شود.
- [ ] از پنل خارج (`خروج`) می‌شوید و دوباره با همان ایمیل/رمز وارد می‌شوید.
- [ ] **تست دسترسی‌ها:** از منوی کناری وارد «کارمندان» شوید و یک کاربر جدید
      با نقش «منشی» بسازید. خارج شوید و با ایمیل/رمز همان منشی وارد شوید —
      باید فقط «داشبورد» را در منو ببیند (نه «پزشکان» و نه «کارمندان»)، کارت‌های
      آمار را نبیند، ولی بتواند نوبت جدید ثبت کند و نوبت‌های پیش رو را ببیند.
      اگر مستقیم آدرس `/dashboard/doctors` یا `/dashboard/staff` را در مرورگر
      تایپ کند، باید خودکار به داشبورد برگردد.

اگر هرکدام از این موارد کار نکرد، پیش از رفتن به فاز بعد (بات تلگرام) باید
اصلاح شود.

## ساختار فنی (برای مرجع)

- `prisma/schema.prisma` — مدل داده (کلینیک، کاربر پرسنل، پزشک، نوبت، تاریخچهٔ
  نوبت‌ها).
- `lib/booking.ts` — قلب ضدتداخل نوبت‌دهی؛ هر رزرو (از هر کانالی) باید از
  همین مسیر عبور کند.
- `lib/auth.ts`, `lib/session.ts` — ثبت‌نام کلینیک، ورود، نشست کاربر.
- `lib/superadmin.ts` — بررسی رمز مدیر کل سامانه (`/superadmin`)؛ فقط مدیر کل
  می‌تواند کلینیک جدید بسازد.
- `app/dashboard/doctors`, `app/dashboard/staff` — صفحات مخصوص «مدیر کلینیک»
  (نقش ADMIN)؛ نقش «منشی» (RECEPTIONIST) به این صفحات دسترسی ندارد و در صورت
  تلاش، به داشبورد برمی‌گردد. این بررسی هم در صفحه و هم داخل Server Actionهای
  مربوطه انجام می‌شود.
- `app/actions/*` — Server Actionهای فرم‌ها.
- `tests/` — تست‌های خودکار (`npm test`).
